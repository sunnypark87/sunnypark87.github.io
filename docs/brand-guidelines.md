# Littlebread Lab 브랜드 가이드

> 지식을 연결해 문제를 해결
>
> Connect Knowledge. Solve Problems.

## 문서 정보

| 항목 | 내용 |
| --- | --- |
| 문서 역할 | Littlebread Lab의 브랜드 정체성과 비주얼 디자인에 관한 최상위 기준 |
| 적용 범위 | 브랜드 언어, 콘텐츠 관점, 시각적 인상, 컬러, 타이포그래피, 그래픽 및 디자인 판단 |
| 현재 단계 | 브랜드 정체성과 비주얼 디자인 원칙 확정 |
| 확정되지 않은 범위 | 구체적인 UI, 페이지 레이아웃, 세부 컴포넌트와 일부 정보 구조 |
| 변경 원칙 | 관심 분야와 콘텐츠 축적에 따라 가변 항목은 별도 논의를 거쳐 갱신 |

이 문서는 앞으로 이 저장소에서 블로그의 디자인, UI, 콘텐츠 구조를 구현할 때 가장 먼저 참고한다. 다만 이 문서에 명시되지 않은 UI 구조를 브랜드의 확정 사항으로 간주하지 않는다.

## 1. 브랜드 개요

### 이름

**Littlebread Lab**

`Lab`은 연구실이나 실험실이라는 강한 의미보다 다음과 같은 개인적인 작업 공간을 뜻한다.

> 새로운 지식을 공부하고, 연결하고, 직접 만들어보는 개인적인 작업 공간

브랜드 철학의 중심은 `Lab`이 아니라 **Connection**이다.

### 목적

Littlebread Lab은 커리어를 위해 공부한 내용과 실제 문제를 해결하며 얻은 지식을 정리하는 개인 기술 블로그다. 학습한 기술이나 개념을 단순히 나열하기보다, 지식을 선택하고 연결하여 해결책으로 구현하는 과정을 기록한다.

Littlebread Lab이 지향하는 개발자상은 다음과 같다.

> 폭넓은 지식을 쌓고, 주어진 문제에 필요한 지식을 선택하여 서로 연결하고 실제 해결책으로 구현할 수 있는 개발자

콘텐츠에서 중요하게 다루는 것은 특정 기술을 얼마나 많이 알고 있는지가 아니라 다음과 같은 **문제 해결 과정과 사고 방식**이다.

- 어떤 문제를 발견했는가
- 문제를 해결하기 위해 무엇을 공부했는가
- 서로 다른 지식을 어떻게 연결했는가
- 어떤 선택지를 고민했는가
- 왜 특정 방법을 선택했는가
- 실제로 어떻게 구현했는가
- 결과를 어떻게 검증했는가
- 어떤 한계와 다음 과제가 남았는가

## 2. 브랜드 언어

### 대표 문구

- Korean: **지식을 연결해 문제를 해결**
- English: **Connect Knowledge. Solve Problems.**

대표 문구는 Littlebread Lab의 가장 짧고 핵심적인 메시지다.

### 핵심 설명 문장

> 지식을 문제에 맞게 연결하여 시스템을 구현하는 개발자의 성장 기록

특정 기술이나 현재 관심 분야에 종속되지 않는 장기적인 브랜드 설명이다.

### 현재 상세 소개 문장

> 퀀트를 공부하며 만난 문제를 컴퓨터과학 지식으로 풀어가는 과정을 기록하는 블로그입니다.

현재의 관심 분야를 설명하는 문장이므로 관심 영역이 달라지면 변경할 수 있다.

## 3. 콘텐츠 방향

현재 첫 번째 주요 콘텐츠 영역은 **퀀트(Quant)**다. 퀀트를 새롭게 공부하며 만나는 문제를 기존의 컴퓨터과학 지식과 개발 경험을 활용해 풀어나간다.

특정 프로그래밍 언어는 브랜드의 핵심 정체성으로 고정하지 않는다. Rust가 주요 도구나 학습 주제가 될 수 있지만 문제 해결을 위한 여러 도구 중 하나이며, 블로그 전체를 Rust 블로그로 브랜딩하지 않는다.

첫 번째 퀀트 프로젝트나 시즌의 구체적인 주제는 아직 결정하지 않았다. 특히 **트레이딩 시스템 구축을 블로그 전체의 메인 프로젝트로 임의 지정하지 않는다.**

## 4. 핵심 브랜드 개념

### Connection

개별 지식을 많이 보유하는 것보다, 문제에 필요한 지식을 찾아 서로 연결하는 능력을 중요하게 생각한다.

```text
문제 발견
→ 필요한 지식 탐색
→ 지식 간 연결
→ 해결 방법 설계
→ 구현
→ 검증과 회고
```

콘텐츠와 디자인 모두에서 이 흐름이 자연스럽게 드러나야 한다.

### 브랜드의 세 가지 태도

| 태도 | 의미 |
| --- | --- |
| Connection | 서로 다른 지식을 문제에 맞게 연결한다. |
| Reasoning | 기술과 방법을 선택한 이유와 판단 과정을 설명한다. |
| Building | 공부한 내용을 이해하는 데서 끝내지 않고 실제 결과물로 구현한다. |

## 5. 비주얼 콘셉트

### Connected Engineering Notes

Littlebread Lab의 핵심 비주얼 콘셉트는 **Connected Engineering Notes**다. `Engineering Notebook`과 `Knowledge Network`라는 두 방향을 결합한다.

#### Engineering Notebook

블로그의 기본적인 읽기 경험을 담당한다.

- 정돈된 기술 문서
- 명확한 정보 위계
- 충분한 여백
- 코드, 표, 다이어그램
- 메타데이터와 수정 기록
- 단계적인 문제 해결 과정

#### Knowledge Network

브랜드의 특징과 지식 사이의 관계를 표현한다.

- 관련 지식의 연결
- 글과 글 사이의 관계
- 프로젝트와 학습 내용의 연결
- 선행 지식과 다음 학습 주제
- 카테고리를 넘나드는 개념 관계

Knowledge Network를 전체 화면의 중심 UI로 사용하지 않는다. 읽기 경험은 Engineering Notebook에 두고 Knowledge Network는 정보 관계를 보여줄 필요가 있는 곳에서 선택적으로 활용한다.

```text
Engineering Notebook 75%
Knowledge Network     25%
```

이 비율은 방향성을 표현하는 기준이며 모든 화면에서 수치적으로 강제하는 레이아웃 규칙은 아니다.

## 6. 비주얼 디자인 키워드

| 키워드 | 의미 |
| --- | --- |
| Connected | 콘텐츠와 지식 사이의 관계가 드러난다. |
| Structured | 정보 구조와 위계가 명확하다. |
| Calm | 오래 읽어도 피로하지 않고 차분하다. |
| Precise | 코드, 데이터, 메타정보가 세밀하고 정확하게 표현된다. |
| Growing | 완성된 지식뿐 아니라 학습하고 구현해 나가는 과정이 보인다. |

## 7. 디자인 원칙

### Content First

장식보다 콘텐츠를 우선한다. 모든 시각 요소는 콘텐츠의 이해나 탐색을 도와야 한다.

### Connection with Purpose

Connection은 핵심 상징이지만 모든 곳에 노드와 선을 넣지 않는다. 다음과 같이 실제 정보 사이의 관계가 있을 때 우선 사용한다.

- 글과 관련 지식
- 프로젝트와 관련 글
- 이전 학습과 다음 학습
- 여러 지식이 하나의 문제 해결로 연결되는 과정

### Structured, Not Boxed

정보는 명확하게 구조화하되 모든 요소를 카드에 넣지 않는다. 다음 순서로 시각적 구조를 만든다.

1. 여백
2. 타이포그래피
3. 정렬
4. 얇은 구분선
5. 필요한 경우에만 카드

카드 안에 카드를 반복하는 대시보드 스타일은 지양한다.

### Quietly Technical

기술적인 인상은 터미널, 네온, 과도한 코드 장식이 아니라 정보 표현의 정밀함에서 만든다.

- 일관된 정렬
- 명확한 메타데이터
- 완성도 높은 코드 블록
- 시스템 다이어그램과 표
- 출처, 날짜와 버전
- 프로젝트 상태

### Visible Growth

완성된 결과만 보여주지 않는다. 필요한 경우 다음 정보를 표현한다.

- Exploring, Building, Completed
- 변경된 판단
- 업데이트 날짜
- 다음 단계
- 시리즈 진행 흐름

단, 게임화된 진행률 UI는 사용하지 않는다.

### Calm and Precise

전체적으로 다음 인상을 목표로 한다.

> 차분하지만 무겁지 않고, 전문적이지만 딱딱하지 않은 기술 블로그

## 8. 컬러 시스템

확정된 팔레트는 **Slate Blue + Warm Brown + Cool Neutral**이다.

### Color tokens

| 그룹 | 토큰 | 값 | 주요 역할 |
| --- | --- | --- | --- |
| Background | Default | `#F8F9FB` | 기본 배경 |
| Background | Surface | `#FFFFFF` | 표면 배경 |
| Background | Subtle | `#F0F3F7` | 낮은 대비 배경 |
| Text | Primary | `#18202B` | 주요 텍스트 |
| Text | Secondary | `#596474` | 보조 텍스트 |
| Text | Muted | `#8993A1` | 낮은 강조 텍스트 |
| Border | Default | `#DDE2E9` | 기본 구분선과 테두리 |
| Border | Strong | `#B9C2CF` | 강한 구분선과 테두리 |
| Brand | Primary | `#365F91` | Slate Blue 기본색 |
| Brand | Hover | `#294B73` | Slate Blue 상호작용 상태 |
| Brand | Subtle | `#E3EBF5` | Slate Blue 저강조 배경 |
| Accent | Primary | `#B47735` | Warm Brown 기본색 |
| Accent | Subtle | `#F4E8D9` | Warm Brown 저강조 배경 |

### Brand — Slate Blue

다음 용도로 사용한다.

- 링크와 활성 메뉴
- 주요 버튼
- 현재 목차
- 선택된 상태
- 중요한 Knowledge Connection
- 브랜드 포인트

### Accent — Warm Brown

Brand Primary보다 제한적으로 사용한다.

- 핵심 인사이트
- 중요한 연결점
- 탐색 중인 상태
- 특별히 강조할 보조 정보

```text
Neutral     85%
Slate Blue  10%
Warm Brown   5%
```

이 비율은 전체적인 색의 우선순위를 나타낸다. 성공·실패 또는 금융의 상승·하락 색상은 브랜드 컬러와 분리된 Semantic Color로 정의한다.

## 9. 타이포그래피

### Primary — Pretendard

다음 영역에서 사용한다.

- 제목과 본문
- 내비게이션과 버튼
- UI와 설명

### Mono — Geist Mono

다음과 같은 기술적 정보와 보조 레이블에 사용한다.

- 코드
- 날짜와 읽는 시간
- 파일 이름과 버전
- 프로젝트 상태
- 기술적인 메타데이터
- 작은 영문 레이블

```text
CONNECTED KNOWLEDGE
CURRENT FOCUS
PROBLEM SOLVING
```

Geist Mono는 일반 본문이나 주요 제목에 과도하게 사용하지 않는다. 기술적 분위기를 만드는 보조 타입페이스로 사용한다.

## 10. 그래픽 언어

Connection을 표현하는 대표 요소는 작은 노드, 얇은 연결선과 관계선, 단순한 그래프 구조, 서로 다른 요소가 하나의 결과로 모이는 형태다.

- 선은 약 `1px` 두께로 사용한다.
- 기본 연결선은 낮은 대비를 유지한다.
- 중요한 연결에만 Slate Blue를 사용한다.
- Warm Brown은 매우 제한적으로 강조한다.
- 실제 방향성이 있을 때만 화살표를 사용한다.
- 노드와 연결선을 단순 장식으로 반복하지 않는다.

## 11. 로고 방향

초기 로고는 텍스트 기반 워드마크를 기본으로 한다.

```text
Littlebread Lab
```

Connection을 약하게 표현한 형태도 후보로 고려할 수 있다.

```text
Littlebread · Lab
```

초기에는 복잡한 심볼을 만들 필요가 없다. 파비콘이나 작은 영역에서는 추후 `LB` 또는 단순한 연결 심볼을 사용할 수 있다. 빵 캐릭터나 빵 모양을 중심 비주얼로 사용하지 않는다.

최종 로고 형태, 파비콘과 심볼은 아직 확정되지 않았다.

## 12. 이미지와 다이어그램

이미지는 분위기보다 설명을 목적으로 사용한다.

### 권장

- 시스템 아키텍처
- 데이터 흐름과 개념 관계도
- 실행 및 실험 결과
- 성능 그래프
- 프로젝트 화면
- 타이포그래피나 간단한 다이어그램 기반 썸네일

### 지양

- 내용과 무관한 스톡 사진
- 의미 없는 금융 그래프
- 장식용 코드 이미지
- 과도한 생성형 이미지 스타일

## 13. 애니메이션

애니메이션은 절제하며 디자인의 중심으로 사용하지 않는다.

### 사용 가능

- 가벼운 Fade
- 링크 Hover
- 현재 연결 관계 강조
- 목차의 현재 위치 표현
- 짧은 상태 변화

### 지양

- 계속 움직이는 배경
- 랜덤하게 움직이는 Knowledge Graph
- 강한 Parallax와 큰 Zoom
- 화려한 페이지 전환
- 자동 타이핑 효과

## 14. 피해야 할 디자인

- 모든 콘텐츠를 카드로 만드는 UI
- 지나치게 둥근 UI
- 강한 그림자와 과도한 Gradient
- Neon 또는 Cyberpunk 스타일
- 전체 사이트를 Terminal처럼 만드는 디자인
- 금융 표현을 위한 과도한 Green 또는 Red 사용
- 장식적인 Knowledge Graph 남용
- 빵 캐릭터 중심 브랜딩
- 의미 없는 애니메이션
- 지나치게 많은 Badge와 Tag
- 디자인을 위해 본문 가독성을 희생하는 것

## 15. 정보 구조의 현재 방향

구체적인 UI는 아직 정하지 않았으며, 기본 정보 구조는 다음을 고려한다.

```text
Home
Articles
Projects
About
```

Articles의 주요 콘텐츠 영역 후보는 다음과 같다.

```text
Quant
Computer Science
Development
Problem Solving
```

이 구조는 실제 콘텐츠가 쌓이면서 변경할 수 있다. Rust와 같은 특정 기술을 블로그의 최상위 브랜드 구조로 고정하지 않는다.

## 16. 미결정 사항

다음 항목은 아직 확정되지 않았으며, 구현 과정에서 이 문서를 근거로 임의 확정하지 않는다.

- 첫 번째 퀀트 프로젝트 또는 시즌의 구체적인 주제
- Home 페이지의 구체적인 레이아웃
- Article 목록 UI
- Article 상세 페이지 UI
- Sidebar 사용 여부
- 구체적인 카드 디자인
- Navigation 상세 구조
- 로고 최종 형태
- Favicon과 OG Image
- 모바일 UI
- 다크 모드
- 세부 컴포넌트 디자인

필요한 시점에 별도 설계를 거쳐 확정하고 이 문서 또는 하위 디자인 문서에 반영한다.

## 17. 구현 및 디자인 판단 체크리스트

향후 Littlebread Lab의 UI나 컴포넌트를 구현·수정할 때 다음 순서로 판단한다.

1. 이 기능이나 디자인이 콘텐츠를 더 이해하기 쉽게 만드는가?
2. 브랜드의 핵심인 Connection을 의미 있게 표현하는가?
3. Connected, Structured, Calm, Precise, Growing이라는 키워드와 어울리는가?
4. Engineering Notebook의 읽기 경험을 Knowledge Network보다 우선하는가?
5. 브랜드 컬러와 타이포그래피의 역할을 일관되게 사용하는가?
6. 불필요한 카드, 장식, 색상 또는 애니메이션을 추가하지 않았는가?
7. 구체적으로 확정되지 않은 UI를 임의로 프로젝트 표준으로 만들지 않았는가?

새로운 디자인을 제안할 때는 단순히 보기 좋다는 이유보다 **해당 제안이 이 브랜드 원칙과 어떤 관계가 있는지** 먼저 설명한다.
